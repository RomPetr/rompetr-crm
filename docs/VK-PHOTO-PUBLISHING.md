# VK: публикация новости с картинкой в сообщество «Разум DEX»

Статус: **план, реализация не начата**. Дата: 19.11.2026.

Цель: при публикации новости из CRM в сообщество «Разум DEX» (VK group id
`243080370`, `club243080370`) на стене появлялся не только текст, но и
сгенерированная PNG-иллюстрация.

## 1. Почему Community Messages не подходит

`Community Messages` — это API личных диалогов «пользователь ↔ сообщество», а не
публикации в стену. Через него нельзя:

- опубликовать новость в ленту сообщества;
- разослать новость всем подписчикам: сообщество может писать только тем, кто
  начал диалог или разрешил сообщения.

Для задачи «пост на стене с картинкой» этот API не используется.

## 2. Текущее ограничение VK

Проверено 19.11.2026 только чтением, без публикаций. Ключ сообщества
`VK_ACCESS_TOKEN` имеет права `photos, docs, messages, wall, manage, stories,
market`, но:

| Метод | Результат |
|---|---|
| `photos.getWallUploadServer` | `error 27: method is unavailable with group auth` |
| `photos.getUploadServer` | `error 27` |
| `photos.getMarketUploadServer` | `error 27` |
| `photos.getAlbums` | `error 27` |
| `docs.getWallUploadServer` | `error 15: User can't upload docs to this group` |
| `photos.getMessagesUploadServer` | работает, но фото сообщения не даёт фото для стены |
| `photos.getOwnerCoverPhotoUploadServer` | работает, но это обложка, не фото для стены |

Это ограничение VK на групповую авторизацию, а не настройка проекта. Текстовая
публикация через `wall.post` работает.

## 3. Рабочая схема (вариант A)

Фото загружается **пользовательским токеном с правом `photos`**, а пост
публикуется текущим ключом сообщества:

1. `photos.getWallUploadServer?group_id=243080370` — пользовательским токеном.
2. Multipart POST файла на полученный `upload_url`.
3. `photos.saveWallPhoto?group_id=243080370&server=...&photo=...&hash=...` —
   пользовательским токеном.
4. `wall.post?owner_id=-243080370&from_group=1&message=...&attachments=photo{owner_id}_{id}`
   — текущим ключом сообщества.

Для VK ID: access token живёт 1 час, refresh token — 180 дней с ротацией,
обязателен PKCE. Обмен кода на токен выполняется на бэкенде и привязывается к
IP бэкенда, поэтому авторизацию и обмен нужно делать на VPS.

## 4. Этапы

### Этап 0. Пилот: проверить, что VK выдаёт токен с `photos`

Без этого этапа код писать нельзя.

1. Создать приложение VK ID (инструкция в разделе 5).
2. Включить расширенный доступ `photos` (или запросить его в поддержке).
3. Авторизоваться под менеджером сообщества `id852659808`.
4. Проверить токен: `photos.getWallUploadServer` и один ручной upload тестовой
   картинки.
5. Если `photos` не выдают или снова `error 27` — вариант A закрыт, переходим к
   запасным вариантам (раздел 7).

Проверку и обмен токена делать на VPS: исходящий IP сервера —
`62.171.228.41`.

### Этап 1. Реализация в CRM

1. `webapp/config.py`:
   - `VK_CLIENT_ID`, `VK_SERVICE_TOKEN` (секрет приложения VK ID);
   - путь к файлу токенов, например `VK_OAUTH_FILE=var/secrets/vk_oauth.json`.
2. `webapp/services/vk.py`:
   - `refresh_user_token()` — обновление access token с сохранением нового
     refresh token (ротация);
   - `upload_wall_photo(image_path)` — `getWallUploadServer` → multipart upload
     → `saveWallPhoto`;
   - `publish(text, image_path=None)` — при успешной загрузке добавляет
     `attachments`; при неудаче публикует текст и пишет предупреждение.
3. `webapp/services/publish.py` — передавать `image_path` в
   `vk.publish(text, image_path)`.
4. OAuth-маршруты `/admin/vk/connect` и `/admin/vk/callback`:
   - только для админа;
   - PKCE и `state` в сессии;
   - обмен кода на токены на бэкенде;
   - токены в `var/secrets/vk_oauth.json`, права `600`, владелец `cpapp`.
5. Тесты: моки VK API на refresh, upload, save, fallback без токена, ошибку 27.
   В CI — без реальных публикаций.
6. Документация: README, `.env.example`, запись в `docs/DEPLOY-JOURNAL.md`.

Особые случаи:

- если `wall.post` упал после загрузки фото, повторять пост с уже полученным
  `attachments`, а не загружать фото заново;
- при неудачном refresh помечать интеграцию как отключённую и публиковать текст
  с предупреждением;
- токены не логировать и не печатать.

### Этап 2. Деплой и проверка

1. `git pull`, обновить `/etc/rompetr-crm/app.env` (только несекретные
   `VK_CLIENT_ID`; секреты — в защищённый файл).
2. Создать `var/secrets/` с владельцем `cpapp` и правами `700`; файл токенов —
   `600`.
3. `systemctl restart rompetr-web rompetr-worker`.
4. Проверить `/healthz`, затем один тестовый пост с картинкой **только по
   отдельной команде владельца**. После проверки при необходимости удалить пост.

## 5. Создание приложения VK ID

Проверено: `id852659808` — менеджер сообщества `243080370` (в списке менеджеров
он один). Исходящий IP VPS — `62.171.228.41` (не `.183`).

1. Открыть кабинет: <https://id.vk.ru/about/business/go>.
   Вход теперь только через **VK Бизнес ID** (`bid.vk.com`). Войти аккаунтом
   `id852659808`.
2. Если профиля бизнеса нет — создать и подтвердить его. Без подтверждения:
   не будет расширенных доступов, включая `photos`; приложение заблокируют через
   60 дней после создания. Для резидента РФ подтверждение идёт через VK Бизнес
   ID (данные организации/ИП), для нерезидента — через раздел
   «Доступы → Расширенные доступы → Заполнить» с банковскими реквизитами.
3. «Мои приложения» → «Добавить приложение».
4. Заполнить:
   - **Название:** `Разум DEX CRM`;
   - **Платформа:** **Web**;
   - **Иконка:** любой квадратный логотип;
   - **Базовый домен:** `rompetr.autos` — только домен, без `https://`, без
     пути и без `www`;
   - **Доверенный redirect URL:** `https://rompetr.autos/admin/vk/callback` —
     ровно так, без слэша на конце.
5. Нажать «Создать приложение».
6. Открыть карточку приложения → «Ключи доступа»:
   - **Уровень конфиденциальности:** **Конфиденциальное**;
   - **IP-адрес сервера:** `62.171.228.41`;
   - нажать «Сохранить».
7. «Доступы» → «Расширенные доступы»:
   - если пункт **«Фотографии» (`photos`)** доступен — включить и сохранить;
   - если пункта нет или он недоступен — отправить письмо в поддержку
     (раздел 6).
8. Из раздела «Информация о приложении» / «Ключи доступа» скопировать:
   - **ID приложения (`client_id`)** — не секрет, можно передать в чат;
   - **Сервисный ключ доступа (`service_token`)** — секрет, в чат не отправлять;
   - **Защищённый ключ (`client_secret`)** — секрет, сохранить.
9. Авторизацию пока не запускать. После получения `client_id` и подтверждения
   `photos` добавить маршрут `/admin/vk/callback`, сгенерировать PKCE/state и
   выдать одноразовую ссылку на авторизацию.

Если кабинет откажется принимать redirect URL (например, проверит его
доступность), создать приложение с `https://rompetr.autos/` и поменять адрес
после добавления маршрута.

Отправить на **devsupport@corp.vk.com** после создания приложения, подставив его
ID:

```text
Тема: Запрос расширенного доступа photos для приложения <APP_ID> (VK ID)

Здравствуйте!

Прошу включить расширенный доступ «Фотографии» (photos) для приложения
VK ID <APP_ID> («Разум DEX CRM», платформа Web, базовый домен rompetr.autos).

Сценарий: мы публикуем собственные новости в сообщество «Разум DEX»
(ID 243080370) через wall.post от имени сообщества. Текст публикуется
ключом сообщества, но для прикрепления иллюстрации нужен пользовательский
токен с правом photos: photos.getWallUploadServer → photos.saveWallPhoto.
Сейчас групповой ключ с включённым правом photos возвращает error 27
(method is unavailable with group auth), поэтому без пользовательского
токена картинку прикрепить нельзя.

Доступ нужен только к photos и только для загрузки изображений в стену
нашего сообщества. Доступ к личным данным, сообщениям, друзьям и другим
разделам не требуется. Объём — несколько публикаций в день. Авторизацию
выполняет владелец сообщества (VK ID 852659808). Приложение
конфиденциальное, обмен кода на токен идёт с IP 62.171.228.41.

Подскажите, пожалуйста, какие ещё данные нужны для включения photos.

С уважением,
<имя>
```

## 7. Запасные варианты

| Вариант | Что даёт | Цена | Ограничение |
|---|---|---|---|
| **A** | настоящее фото в посте | 1–2 дня + токен | VK может не выдать `photos` |
| **B** | карточка ссылки с картинкой | ~1 день | не полноценное фото, а сниппет |
| **C** | ручная публикация | 2–4 часа | руками, но гарантированно |

### B — OG-превью

Публичная страница предпросмотра опубликованного поста с `og:title`,
`og:description`, `og:image` (PNG). В `wall.post` добавляется ссылка — VK
строит карточку с картинкой. Работает с текущим ключом сообщества, без
согласований VK. Минус: это ссылка-карточка, а не фото в посте; VK может
кэшировать превью.

### C — ручной режим

На странице черновика кнопки «Скачать PNG» и «Скопировать текст для VK»,
публикация помечается как `manual_pending` — по аналогии с X. Пользователь
вставляет текст и картинку в VK-композер.

### D — не рекомендуется

- Документ: сейчас `error 15`, выглядит как файл-ссылка.
- `video.save`: требует пользовательский токен и право `video`, которое
  «выдаётся в исключительных случаях».
- Фото, загруженное как фото сообщения: по полевым отчётам 2026 года VK молча
  выкидывает его из поста.

## 9. Безопасность

- `client_id` — не секрет; `service_token` и `client_secret` — секреты, в чат и
  git не попадают.
- Файл токенов: `var/secrets/vk_oauth.json`, права `600`, владелец `cpapp`;
  `var/` исключён из git.
- Access token VK ID — 1 час, refresh token — 180 дней с ротацией; при каждом
  обновлении сохранять новый refresh token.
- Без явной команды владельца боевые публикации в VK не выполняются.
